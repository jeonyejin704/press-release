# PressFlow — 제품 요구사항 정의서 (PRD)

## 1. 배경 및 문제 정의

대학 홍보팀은 연구성과·수상·위원선임·동정·행사 등 다양한 소식을 언론에 알린다.
현재는 Google Form(신청), Outlook 메일(초안·사진·수정 커뮤니케이션), 개별 첨부파일로
업무가 분산되어 다음 문제가 발생한다.

1. 신청 정보와 초안·참고자료·이미지가 분리 관리된다.
2. 메일함 용량 증가, 보도자료별 자료 관리 곤란.
3. 연구진↔홍보팀 수정/재검토/확인 메일 반복.
4. 국문·영문 버전 관리 어려움.
5. 전체 진행 현황·통계 파악 어려움.
6. 언론 보도 수동 검색.

## 2. 목표

신청 → AI 초안 → 검토 → 수정 → 국문/영문 최종본 → 배포 → 뉴스 모니터링까지
하나의 웹 솔루션에서 처리한다.

## 3. 사용자 유형

- **홍보 신청자**: 교수/연구원/행정·사업단 담당자. 신청·AI초안·자료업로드·검토·완료.
- **홍보팀 담당자**: 전체 신청 관리·초안 수정·상태관리·배포일 안내·최종본 확정·대시보드·뉴스.
- **관리자**: 초기엔 담당자와 동일, 사용자/유형/키워드/프롬프트/지표 관리 확장.

## 4. 범위 (MVP)

### In scope
- 역할 기반 로그인(데모), 신청자/담당자/관리자 화면
- 6개 유형 신청 폼, 임시저장/제출
- 연구성과 AI 초안 생성(Mock 기본, Anthropic 연동)
- 신청 목록/상세, 상태 변경, 자료 누락 감지, 체크리스트
- 국문/영문 보도자료 에디터 + 버전 이력
- 첨부파일 업로드(로컬), 코멘트, 감사 로그
- 대시보드(KPI/차트/할 일), 인앱 알림
- 뉴스 모니터링(Mock Provider)

### Out of scope (확장 지점, TODO)
- 실 SSO/이메일/외부 뉴스 API/DOI 자동확인
- 문서 내보내기(Word/PDF), 기자단 배포, 권한/템플릿 편집 UI

## 5. 핵심 사용자 스토리

- 신청자로서 논문 초록을 입력하면 AI 초안을 받아 제출하고 싶다.
- 담당자로서 오늘 처리할 일(보완 필요/검토 대기/배포 임박/지연)을 한눈에 보고 싶다.
- 담당자로서 초안을 수정하되 이전 버전을 잃지 않고 싶다.
- 담당자로서 예상 배포일을 입력하면 신청자에게 자동 안내되길 원한다.
- 신청자로서 내 신청 건만 보고, 최종본을 검토·완료 처리하고 싶다.

## 6. 비기능 요구사항 / 품질 기준

- TypeScript 타입 오류 0, 주요 폼 Zod 검증.
- 빈/로딩/오류 상태 UI 제공.
- 모바일 기본 사용 가능, 관리자 화면은 데스크톱 우선.
- 신청자는 타인 신청 건 접근 불가(서버에서 강제).
- 주요 변경은 AuditLog 기록.
- 파일 URL은 랜덤 파일명으로 추측 곤란, 확장자/용량 제한.
- 개인정보(이름/연락처/이메일/직번) 접근 권한 분리, `.env`는 커밋 금지.

## 7. 성공 지표(예시)

- 신청~최종완료 평균 소요 단계 수 감소.
- 메일 왕복 횟수 감소, 자료 누락으로 인한 재요청 감소.
- 담당자 대시보드 일일 활용.
